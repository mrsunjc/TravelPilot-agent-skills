# 旅行计划可视化输出

## 目标

在完整文字计划之外提供一张可快速浏览的行程信息图。优先保证时间、地点、交通和预算准确，再考虑装饰性生图。

## 两层输出策略

### 第一层：确定性 SVG 信息图

最终计划通过质量门且不存在 `error` 后运行：

```bash
python scripts/travel_visualizer.py final-plan.json \
  --output trip-overview.svg \
  --prompt-output cover-prompt.txt
```

SVG 使用 Python 标准库生成，不需要图片模型或第三方依赖。它展示：

- 目的地、天数、同行人数、强度和预算；
- 每天的片区、时间线、景点、用餐与住宿；
- 相邻停靠点之间的交通方式、时长和估算状态；
- 推荐住宿区、天气摘要和待核验项。

不得为了排版修改计划事实。计划更新后必须重新生成 SVG。

### 第二层：宿主可选 AI 封面

只有宿主已经提供图片生成工具，或用户明确配置其选择的图片 API 时才生成封面。不要假定所有 Agent 都有同一个生图工具，也不要把 Codex、OpenAI 或其他厂商的私有系统 Skill 复制进本项目。

使用 `cover-prompt.txt` 作为宿主中立的提示词基础。AI 图片只负责城市氛围、地标插画和视觉背景，不负责绘制以下内容：

- 行程时间和顺序；
- 门票、天气、预约和交通数字；
- 地图线路或官方标志；
- 大段中文说明。

生图完成后可将本地 PNG、JPEG 或 WebP 嵌入信息图：

```bash
python scripts/travel_visualizer.py final-plan.json \
  --cover-image destination-cover.png \
  --output trip-overview.svg
```

## 宿主能力选择

1. 宿主有内置生图工具：直接使用宿主工具生成封面，不要求用户提供 API Key。
2. 宿主只有外部图片 API：先获得用户明确同意，再要求用户在本地安全配置密钥；不要让用户在聊天中粘贴密钥。
3. 宿主没有生图能力：只交付 SVG 信息图，功能仍然完整。
4. 用户只想要文字计划：不强制生成图片。

## 输出与展示

- 将最终 SVG 和可选封面保存到用户指定目录或当前项目的输出目录，不要写进 Skill 安装目录。
- 在支持本地图片预览的 Agent 中直接展示 SVG；不支持时提供文件链接。
- 若宿主可以把 SVG 渲染为 PNG，可额外导出 PNG，但不得因此引入强制依赖。
- AI 封面和行程信息图应分别保留，便于用户修改计划后只重建信息图。

## 质量与安全

- 先运行 `validate_plan.py`，再生成信息图。
- 质量门存在 `error` 时不得生成看似已经核验的最终图。
- 只有 `warning` 时可以生成，但必须在图中和文字交付中提示待核验项。
- 不把 API Key、Token、证件号、订单号、酒店房间号或用户联系方式写进图片。
- 不使用未获授权的品牌 Logo、地图瓦片、摄影作品或受限制素材。
- 不要求图片模型模仿在世艺术家或受保护品牌的独特风格。
