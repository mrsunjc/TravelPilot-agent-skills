# 输出契约

## 1. 首屏先给结论

开头用简短段落说明：目的地、天数、路线主线、建议住宿区域、强度和关键假设。用户应能立即看懂“每天在哪个片区活动”和“为什么不折返”。

## 2. 景点分级

用表格列出必去、推荐、可选景点，包含推荐理由、建议时长、所在片区和主要限制。用户指定的必去/排除项单独确认。

## 3. 住宿区域

推荐 1–3 个区域，分别说明：适合人群、到主要景点/枢纽的便利性、夜间体验、预算倾向和缺点。只有进行过实时住宿调研时才推荐具体酒店，并注明价格随日期变化。

## 4. 每日行程

每一天必须有：

- 当日地理主线，例如“城南 → 老城，不返回城南”；
- 上午、下午、晚上以及用餐/休息；
- 每站建议到达时间、游玩时长；
- 每段交通方式、距离范围、门到门时间范围和费用范围；
- 票价、开放/预约提示；
- 当日总游览、总交通、步行强度和可删减项；
- 同片区雨天/闭馆备用。

推荐表格列：`时间 | 地点/活动 | 建议时长 | 下一段交通 | 票务/预约 | 说明`。表后再补最重要的执行细节，不重复整张表。

## 5. 抵达与返程

比较机场/车站到住宿区的公共交通和打车方案。最后一天写清退房、寄存、取行李、前往枢纽的顺序，给出最迟离开景点时间和建议到站/到机场缓冲。未给具体班次时明确这是保守模板。

## 6. 票务与动态核验

集中列出核心景点票价、开放时间、停止入场、闭馆日、预约渠道、建议提前期、临时关闭状态、来源和核验日期。无法确认的字段写“待核验”，不留空也不编造。

## 7. 餐饮、预算与物品

- 美食：代表菜品 + 每天路线附近的用餐区域 + 可能绕路/排队的提醒。
- 预算：币种、人数、晚数，以及住宿、餐饮、交通、门票、往返交通、机动金的区间和总区间。
- 清单：证件/预约、衣物、鞋、雨具、防晒、药品、电源、儿童/老人用品；只列与目的地和天气相关的项目。

## 8. 避坑、备选与紧急信息

列出排队、入口、商业化、交通末班、黑车/非正规渠道等可操作提醒。备用方案必须写触发条件，并尽量留在原片区。紧急号码和医院信息注明官方来源与适用地区。

## 9. 最终审计摘要

结尾公开：

- 每天主片区与跨区次数；
- 预计总市内交通时间及其中的估算比例；
- 是否有强度、开放、天气或返程风险；
- 出发前仍需复核的项目；
- 用户补充哪些信息可以获得下一版优化。

发布自然语言版本之前，同时生成符合 `schemas/final-plan.schema.json` 的结构化计划并运行 `scripts/validate_plan.py`。结构化文件是质量审计载体，自然语言版本不得出现与其冲突的票价、时间、路线或预算。

## 10. 路线优化器输入

`scripts/route_optimizer.py` 读取 UTF-8 JSON。最小结构：

```json
{
  "destination": "示例城市",
  "days": 3,
  "intensity": "normal",
  "attractions": [
    {
      "id": "museum",
      "name": "城市博物馆",
      "lat": 34.0,
      "lon": 112.0,
      "zone": "城北",
      "priority": "must",
      "duration_minutes": 180,
      "time_preference": "morning",
      "mandatory": true,
      "available_days": [1, 2, 3]
    }
  ]
}
```

可选顶层字段：

- `party.size`：影响短途交通方式建议。
- `lodging`、`arrival_anchor`、`departure_anchor`：均使用 `id/name/lat/lon/zone`。
- `travel_times`：已核验路线数组，每项为 `from/to/minutes/distance_km/mode/cost/source`；方向敏感时分别提供两条。
- 景点字段 `night`、`closed`、`excluded`、`available_days` 用于约束排程。

强度可写 `light`、`normal`、`commando`，也接受 `轻松游`、`正常游`、`特种兵游`。

输出包含 `days`、`unscheduled`、`data_quality` 和 `audit`。`audit.errors` 代表不可交付问题；`audit.warnings` 需要修正或解释。脚本只负责空间与强度骨架，Agent 仍须把开放窗口、预约场次、天气、用餐和实时交通写入最终方案。
